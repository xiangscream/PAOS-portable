# 配色收敛方法论

从一次 73 页培训 PPT 的实战里提炼。核心不是"怎么替换颜色"，而是"**改之前先搞清楚每个颜色在承担什么职责**"。

---

## 一、先分诊：语义色 vs 装饰色

看到一堆跑出色板的颜色，第一反应不该是"全改成规范色"。先跑 `context.py` 看它长在什么元素上。

| 特征 | 判定 | 处理 |
|---|---|---|
| 伴随「反面示范 / 错误 / 红线 / 禁止」文案 | **语义色（警示）** | 保留红色语义，只统一到同一色值 |
| 伴随「✅ / 解法 / 正确 / 建议」文案 | **语义色（肯定）** | 保留绿色语义 |
| 目录编号块、章节页进度条、章节徽章 | **模块标识色** | 保留「每模块一色」机制，只换色相 |
| 大卡片底（占整页宽）连续若干页 | **模块主题色** | 同上，配合浅底一起换 |
| 无文案的小色块，散落在内容页 | **装饰色** | 直接收敛到规范色板 |

**实战结论**：红色不能一刀切改掉。它在「反面示范」「红线警示」里是语义载体，改成蓝色会直接丢掉警示功能 —— 正确做法是统一成同一个红（如 `#EF4444` → `#DC2626`），而不是消灭它。

## 二、最大的坑：同族两档分不开

这是本次实战里**最贵的教训**。

### 当时的错误做法

一份 6 模块的 PPT，其中 3 个模块用了紫 / 靛 / 绿三个杂色。为了"收回规范色板"，我把它们映射到蓝 / 青 / 琥珀三族的**深色版**：

| 模块 | 原色 | 改成 | 结果 |
|---|---|---|---|
| #1 认识 | `#2563EB` 蓝 | 不动 | — |
| #2 通用操作 | `#14B8A6` 青 | 不动 | — |
| #3 场景实战 | `#F59E0B` 琥珀 | 不动 | — |
| #4 高阶玩法 | `#8B5CF6` 紫 | `#1D4ED8` 深蓝 | **跟 #1 撞** |
| #5 零成本 | `#4F46E5` 靛 | `#0F766E` 深青 | **跟 #2 撞** |
| #6 实操案例 | `#059669` 绿 | `#B45309` 深琥珀 | **跟 #3 撞** |

数据层面完美：配色违规 0、越界 0、溢出 0。**渲染出来才发现，#4 和 #1 的色块几乎一样**，目录页上只能靠高亮边框区分。

### 为什么

- 色相相同、只差明度的两个颜色，在**小色块**（42×42）、**投影**、**远看**时人眼分辨不出来
- 几何检查（越界 / 溢出 / 重叠）**完全检测不到**这类问题 —— 它只存在于视觉层面

### 正确做法

**几个模块就给几个色相，不要用同族两档凑数。**

| 模块 | 色相 | 色值 |
|---|---|---|
| #1 | 蓝 | `#2563EB` |
| #2 | 青 | `#14B8A6` |
| #3 | 琥珀 | `#F59E0B` |
| #4 | **靛蓝**（换色相） | `#6366F1` |
| #5 | **橙**（换色相） | `#F97316` |
| #6 | **翡翠绿**（换色相） | `#10B981` |

配套浅底 / 文字色一并换：`#E0E7FF`/`#4338CA`、`#FFEDD5`/`#C2410C`、`#D1FAE5`/`#047857`。

**验收标准**：把目录页渲染出来，遮住高亮边框，还能一眼数出六个不同的颜色 —— 这才算过。

## 三、识别「分批拼装」的 PPT

一份 PPT 如果是分几次做出来的（尤其常见于培训材料、长期维护的汇报稿），会留下明显痕迹：

1. **配色分段**：前 N 页一套色，中间某页开始换一套，再往后又换
2. **结束页卡在中间**：老版本的最后一页没挪走，新模块直接追加在它后面
   - 这是**结构性硬伤**，检查方法：读每一页的首行文本，看结尾性文案（「谢谢大家」「开始行动」「Q&A」）是不是出现在中间
3. **文案口径过时**：封面写「60 分钟」，目录写「2.5 小时」，各模块时长之和又是第三个数字
4. **页脚分母写死**：增删页后分母不更新；移动页之后硬编码页码全部错位

**检查顺序建议**：先读每页首行文本确认叙事顺序 → 再查时长/页脚等数字口径 → 最后处理配色。

## 四、操作顺序（血的教训）

```
备份 → 体检 → 上下文采样 → 渲染基线（！） → 批量改 → 复检 → 再渲染对比
                              ↑
                    这一步不能省，也不能放在改完之后
```

- **渲染基线要在改之前做**：否则你不知道改动前后的差异是修好了还是改坏了
- **改完必须再渲染一次读图**：这次 v1 就是"数据全绿但视觉翻车"
- 移动 / 删除页后，**立刻重排页脚**，否则整份 PPT 的页码会从某一页开始全部错位
