# 群内日更消息（模板）

用途：每天日会后在项目群发**一条**，替代"口头问进度"。
长度：**8–12 行**，手机一屏看完。

## 结构

1. **一句背景**——现状 + 卡在哪 + 这阶段的目标。
2. **今日** 3–4 条——写结果。
3. **明日** 按域列（驱动 / 控制 / 结构 / 感知），一行一域。

## 已采用的实际样例（2026-10-20）

```
【进度日更】10-20

背景：控制链路已打通，但力矩与电流的对应关系尚未确认；起身动作受限，先把直立与前后运动跑通。
今日
· 解决了 IMU 轴向、遥控板两个遗留问题
· 场地道具-坡道搭建完成，角度可调（5°→10°→15° 逐级）
· 起身受轮电机力矩限制（估算差约 4 倍，轮电机最大电流16.5A，峰值扭矩 2.7 N·m），暂缓；卡地打印件今晚到位
· 力矩与电流的对应关系待实测确认
明日
· 驱动：实测力矩-电流关系
· 控制：吊架拉起后测平衡、调参
· 结构：搭阶梯道具
```

## 边界

- **规格参数可以列**：峰值扭矩、最大电流、角度区间、重量这一级别——读者判断得了轻重。
- **推导与实现不列**：系数换算、相电流/线电流、寄存器量程、代码与接线细节。技术实现由执行者确定。
  - ✅「轮电机最大电流 16.5A，峰值扭矩 2.7 N·m」
  - ❌「−2048~2048 对应 ±16.5 A，0.1 系数下 1 N·m ≈ 10 A」
- **不写过程**：写"搭好坡道"，不写"在搭坡道"。
- **不写评价**：不写"效果不错""有点问题"。
- 卡点没有就写"无"。

## 与文档的关系

- 群消息是**摘要**，文档是**事实源**；群里每条都能在文档里找到位置。
- 文档留全技术细节（给执行者），群消息留背景 + 规格 + 影响（给所有人）。
- **先更新文档，再出群消息**——避免群里先承诺、文档没落地。

## 每天的动作顺序

1. 日会结束 → 拿到要点（或录音，走本地转写）。
2. 汇总进《LRC101 Demo1 A版｜十月开发与实验计划》对应日期章（**追加，不改历史**），技术细节写全。
3. 按本文格式出群消息 → 交项目负责人修改 → 由他发送。
