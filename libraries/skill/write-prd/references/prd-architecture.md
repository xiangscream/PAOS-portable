# PRD 结构选型

## 目录

- 通用文档骨架
- 产品线与预研
- 硬件 PRD
- 软件 PRD
- AI PRD

## 通用文档骨架

### 1. 文档控制

- 标题、项目/产品代号、版本、状态、作者/负责人、更新日期；
- 目标发布版本与里程碑；
- 更新记录：日期、版本、变更、原因、变更人；
- 相关原型、技术方案、规格表、研究和测试链接。

### 2. 执行摘要

- 一句话产品定义；
- 第一目标用户、第一场景、第一任务；
- 本版本目标；
- 首版核心范围与明确非目标；
- 当前最重要的 3–5 个决策。

### 3. 背景与问题

- 用户现状、触发场景、当前替代流程；
- 证据和数据；
- 具体痛点及严重度；
- 为什么现在做；
- 与公司/产品策略的关系。

### 4. 目标与成功指标

每个目标写指标、基线、目标值、观察窗口和数据来源。没有基线时标“需建立基线”，不要伪造数字。

### 5. 系统与体验

- 角色；
- 系统边界和各端职责；
- 关键工作流；
- 状态机、控制权、互斥和数据流；
- 概念模型与关键名词。

### 6. 需求

- 需求总表；
- 按能力域展开详细规格；
- 非功能要求；
- 兼容、迁移和版本策略。

### 7. 验证与发布

- 验收标准；
- 埋点和评测；
- 依赖、风险、开放问题；
- 灰度、回滚、售后/支持和发布清单。

## 产品线与预研

优先写：

1. 市场/用户机会；
2. 候选产品形态；
3. 产品定位与第一任务；
4. 方案对比和当前倾向；
5. 核心参数假设；
6. 技术、成本、可靠性和商业风险；
7. Demo 要验证的假设；
8. 实验条件、观测指标、通过阈值、停止条件；
9. 路线图和决策点。

不要把“Demo 任务分工表”当成产品定义，也不要把“技术能跑”当成用户价值成立。

## 硬件 PRD

建议结构：

1. 产品形态：尺寸、重量、材质、颜色、安装、包装；
2. 系统框图和模块分工；
3. 接口定义：位置、协议、电气、带宽、兼容设备；
4. 物理交互：按键、旋钮、灯、屏、蜂鸣器、触觉；
5. 电源：供电、充电、续航、功耗状态、低电策略；
6. 核心器件和性能参数；
7. 状态机：开关机、休眠、配对、升级、异常；
8. 运动/机械：自由度、范围、速度、精度、负载、稳定性；
9. 影像/音频/传感器规格；
10. 连接、协议、互斥和控制优先级；
11. 环境、可靠性、安全、法规、可维护性；
12. 配件、适配、生产测试、固件升级和恢复；
13. 参数总表、整机默认值、需求优先级和验收。

为每个灯光/声音状态写“触发状态—模式—颜色/节奏—持续时间—优先级—退出条件”。多个状态同时发生时必须定义显示优先级。

## 软件 PRD

建议结构：

1. 平台和最低系统版本；
2. 用户角色、账户、权限；
3. 信息架构和入口；
4. 核心流程/用户旅程；
5. 页面或功能模块；
6. 数据模型、保存和同步策略；
7. 加载、空、成功、失败、禁用、离线、断连、权限拒绝等状态；
8. 输入校验、边界、文案和无障碍；
9. 跨平台/横竖屏/尺寸适配；
10. 性能、安全、隐私和合规；
11. 埋点、灰度、迁移、回滚和发布。

每个页面/功能按此顺序写：

```text
目的 → 入口 → 前置条件 → 默认状态 → 用户操作
→ 系统响应 → 保存/同步 → 异常与恢复 → 权限/兼容 → 验收
```

## AI PRD

除通用需求外补充：

- 用户意图与 AI 负责的决策；
- 输入、输出、模型/规则边界；
- 触发、停止、人工接管和控制权；
- 置信度或不确定性处理；
- 误检、漏检、目标丢失、分布外输入和降级策略；
- 延迟、帧率、资源、功耗和离线能力；
- 数据来源、授权、保留、删除和隐私；
- 评测集代表性、指标、阈值和分场景结果；
- 安全约束、禁止行为和解释/反馈；
- 模型/策略版本、灰度、回滚和监控。

“智能”“自动”“理解场景”必须被拆成可观察输入、决策规则、输出行为和失败回退。

| 参数保存 |  |  |  |  |
| 算法执行 |  |  |  |  |
| 错误恢复 |  |  |  |  |

再定义：

- 状态同步与冲突解决；
- 离线、弱网、断连、重连；
- 固件/App/协议版本兼容；
- 多控制端同时操作的优先级；
- 设备能力探测和功能降级；
- 日志、诊断、售后恢复路径。

## 需求总表

推荐列：

| ID | 一级模块 | 二级能力 | 需求摘要 | 用户价值 | 优先级 | 版本 | 负责人/归属 | 依赖 | 验收状态 |
|---|---|---|---|---|---|---|---|---|---|

详细规格放正文或需求卡，总表用于导航和范围控制，不要把全部细节塞进一个单元格。
