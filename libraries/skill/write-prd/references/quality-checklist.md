## P0 阻断项

出现任一项时，PRD 不应进入研发承诺：

- 第一目标用户、第一任务或首版范围未确定；
- 核心需求互相冲突；
- P0 没有可验证验收标准；
- 安全、隐私、法规或高风险动作没有边界；
- 多控制端/多模式冲突没有优先级；
- 关键参数只有 TBD 且无决策人和截止日期；
- 原型、参数表和正文对同一行为定义不同；
- 关键依赖尚未确认，却被当作确定能力承诺。

## 五轮检查

### 1. 产品正确性

- [ ] 一句话定义具体；
- [ ] 第一用户、场景和任务唯一；
- [ ] 问题与替代方案有证据；
- [ ] 核心能力与第一任务直接相连；
- [ ] 首版核心、支撑、增强、后续、不做已区分；
- [ ] 成功指标衡量用户结果而非功能上线；
- [ ] 最大四类风险有验证方式。

### 2. 结构完整性

- [ ] 文档版本、状态、更新记录齐全；
- [ ] 系统边界、角色和端侧职责清楚；
- [ ] 关键流程、状态机、控制权和互斥已覆盖；
- [ ] 功能、非功能、兼容、迁移、数据、验收已覆盖；
- [ ] 依赖、风险、开放问题和相关资料集中可查。

### 3. 规格可执行性

- [ ] 每条需求有唯一 ID、优先级和版本；
- [ ] 前置条件、触发、行为、反馈完整；
- [ ] 设置有范围、步进、默认值、作用域和持久化；
- [ ] 异步任务有加载、成功、失败、取消、超时和重试；
- [ ] 关键异常有数据保留与恢复路径；
- [ ] “同现有”“见原型”已补关键规则；
- [ ] 不支持能力和非目标明确。

### 4. 可测试性

- [ ] 每个 P0/P1 都有验收标准；
- [ ] 验收覆盖主流程、边界和关键失败；
- [ ] 性能指标带测试条件和统计口径；
- [ ] 硬件指标带公差、环境和测量方法；
- [ ] AI 指标按场景分层并有失败回退；
- [ ] 数据埋点能验证成功指标。

### 5. 一致性与维护

- [ ] 术语、单位、枚举和编号统一；
- [ ] 同一默认值在正文、参数表、原型中一致；
- [ ] 需求总表与详细章节范围一致；
- [ ] 删除/推迟的功能不再出现在适配、埋点或验收中；
- [ ] 所有链接可定位到最新版；
- [ ] 每个 TBD 有当前假设、负责人、日期和影响；
- [ ] 变更记录说明了“改什么、为什么、影响什么”。

## 专项检查

### 硬件

- [ ] 开关机、休眠、配对、升级、异常的完整状态；
- [ ] 灯光/声音冲突优先级；
- [ ] 功耗、低电、过温、堵转、碰撞、断电安全；
- [ ] 接口、电气、协议、兼容和版本；
- [ ] 可靠性、寿命、环境、运输、维修和生产测试。

### 软件

- [ ] 空、加载、禁用、错误、离线、无权限；
- [ ] 返回、取消、切后台、崩溃、重启后的数据；
- [ ] 输入校验、错误文案和无障碍；
- [ ] 多设备/多账户/多端同步；
- [ ] 灰度、迁移、回滚和最低系统版本。

### AI

- [ ] 输入输出和能力边界；
- [ ] 置信度、不确定性和分布外输入；
- [ ] 误检、漏检、丢失、重获和人工接管；
- [ ] 延迟、资源、功耗和离线；
- [ ] 数据授权、隐私、评测集、版本和回滚。

## 评审输出格式

按严重度输出，不要只给泛泛建议：

```text
[P0/P1/P2] 问题标题
位置：
当前写法：
为什么有风险：
建议补充/改写：
影响需求：
```

- **P0**：会导致产品方向错误、安全/合规风险、核心功能不可实现或不可验收。
- **P1**：大概率引发返工、跨端不一致、重要异常缺失或版本范围失控。
- **P2**：清晰度、维护性和次要边界问题。
