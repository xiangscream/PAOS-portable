# 产品定义研究方法论

## Overview

从 LRC101 轮足影像机器人项目的前三周研究中提炼的、经过 GPT Codex 审查和纠偏的产品定义工作方法。核心解决五个问题：

1. **研究顺序倒置**——产品假设未冻结就开始大规模评论采集
2. **桌面推演冒充验证**——矩阵推演不能替代访谈、实测和用户数据
3. **假精确**——BOM、价格、市场规模数字缺乏可审计来源
4. **样本混淆**——众筹支持者/媒体/已购用户/旁观评论混算比例
5. **Agent 职责混乱**——把执行者自审当成独立审查，或未经授权代替产品负责人裁决

本 skill 将上述问题的纠正措施系统化为可复用的方法论。

## 核心原则

### 正确的研究顺序

```
决策问题 → 产品假设 → 竞品边界 → 证据缺口 → 定向取证 → 反方审查 → 综合决策
```

**不是**：先搜竞品 → 边搜边改定义 → 抓评论 → 拼结论

### 产品定义的本质

产品定义不是"描述这个产品做什么"，而是回答七个问题：

1. 为谁做（第一目标用户，不是"大众消费者"）
2. 在什么场景下用（主场景，不是功能列表的并集）
3. 解决什么现有方案解决不了的问题
4. 为什么现有方案不够（必须具体，不能只说"不够好"）
5. 为什么是现在（供给侧/需求侧/技术侧的汇聚点）
6. 明确不做哪些（排除项比功能列表更重要）
7. 3000 元（或其他目标价格）到底能不能闭合

### 永远先写"不做"清单

产品定义的第一个产出不是功能列表，而是明确排除的方向。排除项必须具体，不能是"暂不考虑某些场景"。

排除项必须分两层，不能一刀切：

**硬排除**（与产品假设根本矛盾，首发不做）：
- 与核心技术路线、目标用户或产品定位直接冲突的方向
- 示例：产品定位"户外优先"，则室内监控场景为硬排除

**软约束**（能力到位后自然覆盖，但不主动营销承诺）：
- 与产品能力方向一致，但主动承诺会引入不可控的安全/可靠性风险
- 示例：人物跟随能力对儿童年龄透明，但不承诺"儿童安全"
- 示例：底盘速度和防护达标后自然适用滑板/跑酷，但不标"极限运动专用"
- 示例：生命感和动作反馈是产品核心体验，但不支持长期人格记忆和情感依赖

格式示例：
```
【硬排除】与产品假设根本矛盾，首发不做：
- 室内监控（与 Outdoor-first 矛盾）
- 纯 AI 宠物无拍摄（与 Camera-anchored 矛盾）

【软约束】能力到位后自然覆盖，但不主动承诺：
- 儿童跟随 → 不承诺儿童安全，但跟随便年龄透明
- 极限运动 → 不标"运动专用"，但速度/防护达标后自然适用
- 电子陪伴 → 不支持长期人格，但生命感是核心体验
```

任何重新加入硬排除方向的请求，必须附带：
- 新证据是什么
- 改变哪个决策判断
- 为什么值得扩大产品范围

## 五 Gate 研究推进

每个 Gate 有明确的通过条件和交付物。先读取现有决策与证据，已满足的 Gate 不重复执行；局部补证只处理对应缺口，不重新启动整套研究。未满足的关键通过条件不能因省略流程而视为通过。

### Gate 0：冻结产品假设与排除项

**目标**：所有参与者对研究对象形成一致理解。

**必须回答**：
- 目标价格为什么是这个区间，而不是更低或更高？
- 为什么必须某个技术路线（如户外/轮腿/小尺寸）？
- 为什么功能锚点是这个而不是那个？
- 为什么没有某项前沿技术时产品仍可成立？

**交付物**：
- 产品假设文档（含价格、尺寸、用户、场景、功能锚点）
- 一页"做/不做"边界表
- 待验证假设台账

**通过条件**：人工确认。未经确认，不得开始大规模评论采集。

同一研究范围已有明确人工确认时，引用该确认并继续，不重复申请。新增大规模采集或实质改变研究范围仍需按上述要求确认；本规则不扩大批准权限。

### Gate 1：竞争空间与价格带

**目标**：证明产品定位的"中间楔子"是否真实存在——不是被上下两端挤压的夹层。

**竞品卡格式**（每张卡只回答 8 个问题）：
1. 产品形态和实际交付状态（概念/众筹/已发货/停产）
2. 公开价格与抓取日期
3. 第一购买理由（用户为什么掏钱，不是厂商为什么做）
4. 核心使用场景
5. 核心技术是否是产品核心价值
6. 拍摄/影像/记录是主功能、功能锚点还是附加功能
7. 用户为什么不用更便宜的替代方案
8. 对本产品的价格、尺寸和功能边界有什么影响

**禁止**：
- 按关键词无限扩品
- 把感知摄像头当影像能力
- 把概念展示当已上市产品
- 用厂商宣传语作为事实

**通过条件**：形成可解释的价格—尺寸—能力地图，判断目标区间是否有空位。

### Gate 2：需求与用户证据

**目标**：验证用户为什么买、为什么带出去、为什么三个月后还用。

**研究顺序**：先分析任务和替代方案 → 再访谈目标用户 → 最后用评论补充。不能反过来。

**访谈最少问**：
- 最近一次想记录但没人拍是什么时候？
- 当前怎么解决？
- 一个月真实发生多少次？
- 愿意多携带多重、多大的设备？
- 2999/3999/4999 元分别需要哪些能力才会买？
- 可爱/会跳、会跟、拍得好，哪个最影响购买？
- 过去买过哪些新奇设备、为什么闲置？

**评论采样要求**：分层不混算。众筹评论→购买前期待；媒体体验→短时表现；已购用户→长期使用；论坛旁观→市场认知。

**通过条件**：至少找到一个"每月真实发生、普通方案明显不足、用户愿为增量付费"的任务。

### Gate 3：技术、成本与公司能力

**目标**：判断目标价格是否能在不牺牲产品成立条件的前提下闭合。

**公司能力分级**：
- **A 已商品化**：可直接复用
- **B 可迁移待验证**：需要实测确认
- **C 明显缺口**：需要外部合作或自研
- **D 长期战略**：首发不依赖

**必须由内部确认**（不能用公开资料替代）：
- 核心器件 BOM 与目标售价的 COGS 倒推
- 关键技术的迁移可行性
- 量产、售后和责任边界

**通过条件**：成本、尺寸、续航、可靠性四项不存在不可调和的矛盾；确认首发不依赖 D 类能力。

### Gate 4：综合决策

**必须输出三案**：
1. **推荐推进**：何种证据出现后可提高优先级
2. **保守验证**：以何种方式继续减少不确定性
3. **暂缓**：哪些失败条件意味着不应继续

**禁止**：
- 用综合评分掩盖致命短板
- 因为长期战略有价值就跳过近期产品成立条件
- 因为竞品少就说市场空白
- 因为竞品多就说需求已验证

**决策报告最终必须给出**：
```
建议选择：推荐 / 保守 / 暂缓
目标产品假设：
首批用户与场景：
价格与尺寸目标：
已验证证据：
仍未验证：
公司优势：
公司缺口：
下一阶段最小验证：
停止条件：
```

## Agent 角色分离

按判断影响安排角色。DS-H 等执行者可以在任务包内完成检索、分析、草拟和初审，并自行修订；自审须如实标为自审。主管独立抽查支撑关键结论的证据，高影响交付需独立审阅。执行者不得代替产品负责人接受产品承诺或重大取舍。

下表用于需要专门分工的任务，不要求普通工作为每种角色另开一个 Agent。兼任时区分事实、分析和自审；独立审查仍须由另一审阅者完成。Reviewer 可以指出替代解释与需补证方向，但不得绕过任务授权将其写成正式决策。

| 角色 | 只做什么 | 禁止做什么 |
|------|---------|-----------|
| **Evidence Scout** | 找官方规格/价格/交付状态/独立实测/原始评论；保存完整 URL 和日期；标记矛盾信息 | 写市场结论；自行扩品；拼成新事实；估算数字 |
| **Competitor Analyst** | 每次只处理一个竞品证据包，按 8 字段输出竞品卡 | 改变产品定义；把推断写成事实 |
| **User Evidence Coder** | 按固定字段编码用户阶段/场景/动机/价格态度/问题/留存信号 | 合并不同平台样本计算总体比例 |
| **Technical Analyst** | 只写可审计来源的技术参数 | 填入"看似合理"但无来源的数字 |
| **Reviewer** | 检查证据和推理；提出反例、替代解释与必要补证方向 | 未经授权重写全文；把审阅意见直接变成产品决策 |
| **Synthesizer** | 只读取审查通过的素材，汇总为决策报告 | 引入新产品；把 UNKNOWN 自动补全 |

## 六字段任务包

每个派给 Agent 的任务必须包含六个字段：

```markdown
任务目标：（一句话）
允许使用的输入：（明确列出来源文件/URL）
明确排除：（不能做什么、不能加什么）
输出模板：（固定格式，Agent 填空）
完成定义：（怎样算完成）
遇到不确定时：标记 UNKNOWN，不自行补全。
```

### 正确 vs 错误的任务示例

✅ 正确：
- "只核验 Beni 当前价格、状态和官方功能，不做市场判断"
- "只将以下 20 条评论按给定字段编码，不统计比例"
- "只审查这张竞品卡中事实与推断是否混淆"
- "只比较 TAMO 与目标产品的移动地形和价格，不加入新产品"

❌ 错误：
- "研究所有竞品并给出产品定义"
- "看看市场怎么样，顺便写报告"
- "继续发散更多场景"

## 五标签证据体系

所有输出必须区分信息类型。Agent 不得自行升级标签。

| 标签 | 定义 | 例子 | 谁能升级 |
|------|------|------|---------|
| **FACT** | 可核验事实 | 官方售价、重量、交付状态 | — |
| **USER_SIGNAL** | 用户原话/表达 | "我想用它拍狗" | — |
| **INFERENCE** | 基于事实的解释 | 低视角可能适合宠物内容 | 总控审查后可升级为假设 |
| **HYPOTHESIS** | 等待验证的判断 | 玩乐比拍摄更驱动购买 | 总控确认证据后可升级为阶段判断 |
| **DECISION** | 负责人确认的选择 | 排除室内监控主场景 | 只有产品负责人可做出 |

## 证据等级

- **A 级**：内部确认、官方规格、监管/财务文件 → 可进入决策
- **B 级**：独立实测、可复现实验 → 可进入决策
- **C 级**：用户自述、论坛评论 → 仅支持方向性判断
- **D 级**：厂商宣传、媒体转述、合理推断 → 不可单独支撑结论
- **U 级**：来源缺失或冲突 → 不能进入正式结论

## 数字规则

每一个价格、销量、频率、BOM、速度、续航数字必须标注：
- 原始来源（URL，不是"CSDN/雪球"）
- 抓取/确认日期
- 币种与税费
- 样本或适用条件
- 是否厂商宣称
- 是否会动态变化

无法满足时删掉精确数字，改为方向性描述。

## 固定系统提示

派给 Claude/DeepSeek Agent 执行具体任务时使用：

```text
你是本项目的研究执行 Agent，按任务包的目标、范围与验收标准工作。
可在授权范围内自行检索、分析、草拟、自审和修订。自审不冒充独立审查。
不得擅自改变已接受的产品定义或自行作出产品最终决策；任务包明确排除的对象不纳入正式交付。
有依据的范围外机会可以作为提案报告主管，不自行扩大执行范围。
所有输出必须区分 FACT / USER_SIGNAL / INFERENCE / HYPOTHESIS / DECISION。
没有可核验来源的数字必须写 UNKNOWN，不得估算。
众筹、厂商宣传和媒体体验不能证明长期需求或量产可靠性。
阶段完成后保存确切产物及证据位置，报告变化、初审结果和下一步建议；需阶段验收时等待主管放行，不让用户重复确认已授权的常规修订。
```

## 任务失败处理

出现以下任一情况，任务退回重做：
- 新增了任务外竞品
- 没有完整来源
- 把宣传语写成事实
- 超出任务包授权输出市场结论，或将推断写成已接受决策
- 使用未经提供的精确数字
- 没有区分购买前期待和已购体验
- 没有按输出模板交付

同一任务失败两次后，不再调整角色或重写流程，缩小为更机械的提取工作。

## 总控派任务前检查清单

- [ ] 这个任务会减少哪个决策不确定性？
- [ ] 产品边界是否已经给 Agent？
- [ ] 是否限定了输入和输出？
- [ ] 是否明确禁止扩品和扩场景？
- [ ] 是否要求完整来源？
- [ ] 是否区分事实、用户信号和推断？
- [ ] 是否有人工审查点？
- [ ] 如果 Agent 完美完成，下一步决策是什么？

如果最后一项答案是否定的，这个任务不值得派。

## 适用边界

本 skill 适用于：
- 新产品方向探索（尤其是硬件/机器人/消费电子）
- 品类边界模糊、需要先定义再研究的项目
- 多 Agent 协作的复杂研究工作
- 试用期/新岗位前 30 天的产品方向研判

不适用于：
- 已立项产品的 PRD 撰写（此时产品假设已冻结）
- 短期竞品监控（不需要完整 Gate 流程）
- 单次事实查询（不需要角色分离和证据体系）
