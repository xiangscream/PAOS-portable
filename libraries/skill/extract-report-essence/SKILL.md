# 提取报告精华版

将“精华版”视为一份可独立阅读的管理决策文档，不是逐段压缩、宣传稿或脱离证据的重写。保留全量报告作为证据库；精华版只呈现会改变判断、优先级或后续动作的信息。

## 先确定交付边界

1. 确认输入是本地 Markdown/文档、飞书云文档，还是两者。读取完整正文；长文先读取目录，再按章节和关键词分段获取，直到覆盖结论、关键证据、风险、限制、行动建议、附录和来源。
2. 确认精华版的读者。未指定时按“管理层/导师汇报”处理：优先战略判断、产品含义、风险和验证动作，不按原文篇幅平均压缩。
3. 创建**新的独立文档**。不得编辑、覆盖、移动或改名原报告。标题默认使用“原报告标题｜管理精华版”；用户指定标题时优先用户标题。
4. 在精华版开头放置原报告可点击链接，并明确全量证据、来源、冲突台账、附件或媒体仍以原文为准。

使用飞书时，先阅读并遵循 `lark-doc` 及相关 `lark-cli` Skill 的当前操作规范。处理本地 Markdown 时，保留源文件不修改。

## 建立决策骨架

先从完整材料中抽取下列字段，再开始写作。信息缺失时写 `UNKNOWN` 或“原报告未证明”，不得用常识补全。

| 字段 | 要回答的问题 |
|---|---|
| 核心结论 | 应推进、验证、暂缓或维持什么？其前提和边界是什么？ |
| 固定目标/评价标准 | 原报告用哪一句话或哪组标准衡量成败？逐字保留固定目标。 |
| 已证实 | 哪些事实、实测、用户信号或可审计材料足以支持当前判断？ |
| 未证实/风险 | 哪些能力、市场、交付、合规、成本或长期使用问题尚无充分证据？ |
| 决策含义 | 这些证据对市场、产品、技术、组织和商业模式意味着什么？ |
| 下一步 | 应验证什么、由什么证据关闭、什么条件下停止或升级？ |
| 证据边界 | 团队自述、视频观察、用户评论、推断和独立事实各自能证明什么？ |

不要机械照抄原章节。按决策链重组：**结论 → 评价目标 → 能力/市场裁决 → 已证实价值 → 未证实风险 → 后续输入 → 证据边界**。如果原报告已有更适合的固定框架（如 Gate、3+1、竞争分层），保留并压缩该框架，而不是另造模型。

## 证据与措辞规则

1. 原报告中的核心结论、固定目标、否定性结论、关键数字、条件限制和证据标签必须原样保留或忠实等义转述，不得反转强度。
2. 将“厂商/团队称”“路线图”“视频直接可见”“用户表达”“分析推断”严格分开。不得把团队自述升级为独立实测，不得把视频观察升级为算法/结构内部事实，也不得把众筹热度等同于 PMF、零售转化或留存。
3. 保留原有 `FACT`、`FACT-O`、`FACT-T`、`STAFF-DISCLOSURE`、`VIDEO-OBS`、`USER-SIGNAL`、`INFERENCE`、`UNKNOWN` 等标签；若精华版不逐条展示，在“证据边界”中说明标签体系以原文为准。
4. 每个“已证明”都写清对象与条件；每个“未证明”都写清缺少的证据。避免“显然”“一定”“行业普遍认为”等无来源加强语。
5. 不引入原报告外的竞品、事实、价格、市场规模、用户比例或技术判断。若用户要求补充外部资料，先与原结论分开标注，并保留来源和日期。

## 写成可汇报的精华版

采用短段落、明确标题、表格和有限要点，避免把原文的大段叙述原样搬运。默认结构如下；按原报告特征增减，但不要添加与决策无关的模块。

```markdown
> 版本：原报告标题｜管理精华版
> 适用：决策场景
> 全量证据、来源与附件见：[原报告](原报告链接)

---

## 核心结论
> 一段可直接引用的结论，包含方向、价值、关键未证实项和边界。

## 一、固定目标/问题定义
> 原文固定目标或评价标准；不得随意改写。

## 二、关键裁决
| 核心问题 | 当前裁决 | 已有信号 | 尚未证明 |

## 三、已被证明的价值
1. …

## 四、尚未被证明的关键能力与风险
### 1. …

## 五、对后续讨论的直接输入
1. …

## 六、证据边界
…
```

适用时将原有 Markdown 表格转为飞书原生表格。表头必须简短、列宽适合阅读；一个表只服务一个决策问题。长段正文拆为“判断句 + 依据/边界”，但不能为了版式删除限定条件。

## 飞书创建与呈现

1. 用飞书原生文档创建精华版，写入标题、标题层级、引用块、原生表格和可点击原报告链接。
2. 优先采用克制的管理汇报版式：清晰标题层级、短摘要、表格对齐、关键结论引用块。不要为了“美化”添加封面、图表、色块、卡片或新内容，除非用户明确要求。
3. 原报告含图片、视频或附件时，不默认复制全部素材。精华版只保留会改变核心判断的媒体，并链接回全量报告；除非用户明确要求媒体嵌入。
4. 多次调用飞书编辑接口时，使用乐观并发控制/最新 revision；出现冲突时重新读取受影响块，再合并，不覆盖其他人修改。

## 验收

完成前逐项检查：

- 原报告和本地源文件均未修改。
- 已创建一个新文档，标题、链接和访问地址正确。
- 核心结论、固定目标、已证实/未证实边界与原报告一致。
- 关键表格不截断，链接可点击，中文标题层级正确。
- 没有把 `UNKNOWN` 自动补全，没有把宣传/观察/推断写成已验证事实。
- 回读新文档的标题、核心结论、固定目标和至少一张关键表，确认写入成功。

最终回复只说明新文档已创建、给出链接、概述精华版包含的决策内容，并说明原报告未被改动。
