# 产品功能结构图

## 什么时候用

- 用户要一张「能从用户侧把所有功能层次清晰地展示出来」的图
- 用户说图「乱」「同级不对等」「呈现不了层次关系」
- 需要把一长串功能清单整理成模块层级

## 一、开工前自查（决定这张图成败的四件事）

**"同级不对等"是功能结构图最常见的失败模式。** 先查这四条，再动手画：

1. **跨模块重复**——同一个功能在多处出现（例：`目标确认` 同时在"公共能力"和某个模式里；`Hold`/`Mark` 在三个模式各列一次）。违反 MECE 的"同层相互独立"。**公用功能只列一次，放公共模块，各分支内不再重复。**
2. **模块与取值混级**——把"设置项"和"它的取值"摆成同级（例：`拍摄关系` 和 `Rear/Side/Front` 相邻）。**取值只能是它下面一层的文字或叶子节点。**
3. **异常/边界混进并列功能**——`异常退出`、`执行偏差处理` 和 `Shot`、`连续跟随` 并列。**要么改写成正向能力名（`中断与安全恢复`），要么移出模块层级。**
4. **一级模块名本身是混合维度**——例：`入口与控制` 一个名字塞了"入口＋控制＋反馈＋结果"。**一级必须是一个统一维度**（按功能归属、按用户任务阶段、或按使用方式，三选一），否则下面怎么排都不对等。

## 二、结构配额（超过就该拆或合）

| 项 | 要求 |
|---|---|
| 一级模块 | 4–8 个 |
| 每个一级下的二级 | 3–7 个 |
| 总层级 | ≤ 3 层（根 → 一级 → 二级 → 三级） |
| 同层粒度 | 完全一致：同层要么全是"配置类功能"，要么全是"执行类功能"，不混 |
| 叶子命名 | 动词＋宾语（`设定跟拍关系`／`编排镜头`）；名词型只在确实是名词时用（`声音链路`） |
| 分组依据 | 按**用户目标**分组，不按技术实现分组；不出现技术名词 |
| 边界清理 | 约束条件、技术实现、交互流程**移出**模块图——它们不是模块层级 |

## 三、两种布局

- **自上而下**（默认）：根在顶部居中，一级横向排开，二级在各列向下堆叠。中文功能结构图的常规方向。
- **横向**：根在最左，向右逐级展开。列多时更省高度，但飞书文档里不如纵向好读。

无论哪种，**每条分支都要有可见的连线**。靠"列位置"暗示层次会被判定为"没有层次关系"。

### 关于"展开某几个二级"

用户经常会点名"把某几个二级展开"（例：Shot 展开成五个镜头类型）。做法：

- **只展开被点名的少数二级**，其余维持两层。全展开会让节点数爆炸，也失去"结构图"的作用。
- 展开后的子节点用**左主干＋短横枝**，主干挂在展开组组长节点的下缘；子节点缩进 30–60px，宽度比二级窄一档，层级靠缩进＋连线区分，不靠换色。
- 展开组的组长节点给**语义浅底＋语义描边**（其余二级是白底灰边），一眼能看出"这个还有下一层"。
- **子节点一律"名称＋短注"**（短注 ≤6 个汉字），细则留在正文表格里，不往图上堆。

## 四、生成 SVG

用 `scripts/tree_gen.py`（自上而下、支持 `item` / `group` 两种块型，改 `MODULES` 数据即可跑）：

```bash
python scripts/tree_gen.py            # 输出 fg-tree.svg
```

脚本已处理四件容易踩的事：

1. **按词边界换行**——ASCII 连续段（`Front`、`Height`、`Target Tag`）作为不可拆 token，避免出现 `F / ront` 这种截词。
2. **画布高度自算**——按换行后的实际行数累加，不靠估。
3. **节点文字溢出检查**——`fits()` 在放"名称＋短注"前先量宽度，放不下就退回居中单行。**改完文案必须跑一遍检查**，中文全角宽度是按 `fs` 算的，很容易差几十像素。
4. **配色**——语义固定（公共/交互=琥珀 `#FAF6EE`/`#B59B6B`、感知=蓝 `#F2F6FA`/`#7A95B5`、决策=紫 `#F4F2F8`/`#9890B0`、执行=绿 `#F2F7F3`/`#7A9D85`）；一级＝语义浅底＋语义 2px 边，普通二级＝白底 `#D0D5DC` 1px 边，根＝`#4E5A6B` 底白字。**不要用 600 级实心色块做大面积填充**（飞书专业文档场景的配色铁律，见 `feishu-cli` skill 的分色规范）。

## 四点五、★ 本地渲染自检环（2026-09-24 实测固化 · 少了这步必返工）

**不要写完 SVG 就直接传飞书。** 飞书回读一轮要 30 秒以上，而布局错误（重叠、溢出、算错画布高）几乎必然出现。先在本地用无头浏览器渲染成 PNG 看一眼，改到干净再传。

```bash
# 1) 写一个只有 <img> 的预览页
cat > preview.html <<'EOF'
<!DOCTYPE html><html><head><meta charset="utf-8">
<style>html,body{margin:0;padding:0;background:#fff}img{display:block;width:1600px}</style>
</head><body><img src="flow.svg"></body></html>
EOF
# 2) 无头 Edge 截图（Windows 自带，无需额外装东西）
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless=new --disable-gpu \
  --screenshot="C:\path\out.png" --window-size=2030,2500 \
  "file:///C:/path/preview.html"
```

- `--window-size` 必须 **≥ 画布 viewBox**，否则截不全（表现为"最后几个阶段不见了"，别误判成生成器 bug）。截图前先 `node gen.js` 打印出实际 viewBox 尺寸。
- **首次调用可能返回 exit 2 且不出文件**；去掉 `>/dev/null` 让它直接输出、或原样再跑一次即可成功。**失败时不要改参数猜，先看是否已生成**。
- 看 PNG 时按这个顺序查：① 左右两栏有无重叠 / 溢出画布；② 各阶段是否全部出现；③ 卡片内文字有无被裁；④ 底部留白是否过多（画布高按内容实际底部算，不要写死）。

**布局三定律**（本轮踩全了）：

1. **画布高必须由内容底部算出，不能写死。** 先声明 `let H`，末尾 `H = Math.max(右栏末端, 左栏末端) + 余量`，底板 `<rect>` 用算出的 H 最后拼到最前。
2. **分栏必须验算坐标，不能凭感觉。** 左栏右边界、卡片右边界、右侧标签右边界三者要写成常量并 `node -e` 打印出来比一遍。典型错误：侧边标签 `x` 落在卡片区里（重叠）、或超出栏宽（溢出画布）。
3. **中文宽度靠近似测量 + 逐级降字号。** 写一个 `measure(s, size)`（CJK 按 `size`、ASCII 按 `0.55*size`），标题放不下时 `while (measure(t,ts) > maxW && ts > 20) ts--`，而不是硬换行或任其溢出。折行函数要按**字符**累加判断，不要按空格切（中文没有空格）。

- **生成的流程图/结构图画在独立 `.js` 生成器里**（`xxx_gen.js` 输出 `.svg`），不要手写 SVG。改一处布局只改一个常量，比在 30KB 的 SVG 里找坐标快一个量级。

## 五、落到飞书画板

- 直接上传 SVG（`lark-cli whiteboard +update --whiteboard-token <t> --input_format svg --source @./x.svg --overwrite --as user`，source 是**纯 `<svg>`**，不带 `<whiteboard>` 包裹）。
- **新建画板走"占位 + 写内容"两步**（lark-cli v1.0.70 无 standalone create）：先 `block_insert_after` 插一个极简空 `<whiteboard type="svg">`，从返回 JSON 的 `whiteboard_token` 取值，再 `whiteboard +update` 写入真实 SVG。注意返回里 `block_token`（文档 block 副本 id）≠ `whiteboard_token`（云端画板 token），要用后者。
- **回读验证用 `whiteboard +query --output_as image`** 导出云端 PNG 看真实渲染效果，这是唯一可信的验收。**不要只看 SVG 本地渲染就宣布完成**——飞书解析器对某些写法会静默丢弃元素。
- **字号要补偿**——飞书 web 把画板按容器宽度（约 800px）等比缩放。以 viewBox 1600 为基准：画布主标题 30–34 / 一级节点主文 30–32 / 普通节点主文 26–30 / 副文与注释 19–22。画布更宽时按 `1600/W` 反比放大。**严禁用 17/12/11px**，飞书里会糊成蚊子字。
- 画布宽 1600–2000、高 1200–1500 是舒适区间。内容太多时**优先拆成多张画板**，不要压字号。
- **SVG 约束**：可用 `<rect>/<line>/<text>/<path>`；**不用** `radialGradient` / `filter` / `pattern` / `clipPath` / `mask`。全局 `font-family` 用 `Arial` 时中文会用系统字体兜底，不会乱码。
- 导出 PNG 眼验时**先 sleep 2–3 秒再导**，否则抓到空帧。
- **附一份 HTML 预览**（把 SVG 内联进去，提供"适应宽度 / 原始大小"切换）——大图在飞书里要缩放才看得清，HTML 现场评审更方便。

## 六、交付前自检一句话

拿给一个没参与过项目的人看：**他能不能只看这张图，说出这是哪几块、每块下面有什么、哪一层是同一类东西？** 说不出来就是还没排对。
