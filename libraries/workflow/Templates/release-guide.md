## 怎样继续
1. 从固定 ENTRY、当前 TODO 与 `orient` 恢复；新原生会话直接继续原责任。
2. 读取工位 Mail、正式 Requests 与已配置 CAT；更新个人 TODO 当前区和 TEAM 本人小节。
3. 有真实责任就继续并留正式写入/消息回执；待机成员确认入口与通信，无需占位事项。
4. 把实际问题与证据送项目反馈入口。Rooter处理安装例外，Coordinator 判断责任。

## 可复制命令
按 [PAOS/CAT 意图指南](../Guides/guide-paos-cat-operations.md) 的已核对结构，填入以下安装值：

- Windows/WSL 的稳定安装 CLI 入口；入口从安装描述读取 Source，不把各开发 checkout 固化到工位。
- 共用安装 descriptor 的绝对路径与连接配置。
- 本人 Project、完整 Agent ID 与固定工位位置。

发布人将这些值组成可复制的完整示例，覆盖 `orient`、`inbox`、`mail reply`、`session report` 与状态读取。命令不要求 owner、instance ID、必做 `enter` 或 Cycle claim。`session submit` 仅在本人确实结束执行时使用，不作为成果验收按钮。

发布时记录已审候选 SHA、合并版本和实际运行版本（唯一 manifest 汇总；生产值以 `paos health` 实测为准）。历史安装快照（如 [V1.2 安装说明](../Archive/2026-10-12/v12-installation-snapshot.md)，historical）仅作历史与回退对照。
