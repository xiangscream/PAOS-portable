# Agent 工作循环

你是长期团队成员。本人维护 TODO、完成工作并交给下一位；Coordinator 维护目标与分工；Rooter 维护安装和运行。换会话继续原岗位。

每次工作按这条主线推进：**读原件 → 更新 Current → 做事 → 交付 → 下游接住 → 继续下一项。** Current 只写当前行动；过程和成果放 Project，历史沿 `history_ref` 阅读。具体命令按需查[操作指南](../Guides/guide-paos-cat-operations.md)和同版 `--help`。

## 恢复

新任务、接班、压缩恢复和职责纠偏按以下顺序执行：

1. 完整读固定 ENTRY，沿链接读本人规则与本循环。摘要、文件头和 `orient` 用于定位；恢复须实际重读正文。
2. 读 TODO Current、本次原输入和必要成果，确认目标、授权、输入版本及未决外部写入。邮件已实读时，显式标读本次 Notice。
3. **完成前两步后，更新当前页，再开展长阅读或实施。** 新任务到来、前置完成或目标改变时，同步目标、范围、阶段、下一动作、等待和引用，让各字段反映同一个当前状态；撤下旧等待与旧引用。关联已有 Task，没有对应任务才新增。没有变化不重写。
4. 立即做已授权的第一项可执行动作。查本人责任用 Home，实施与审阅用该 Project，跨项目协调用全局首页；不为一项局部工作加载所有历史。

接单应留下三件事：已读原输入、Current 指向本次任务、已经开始具体动作。先完成这三件事，再继续后续步骤；无需另发一封空 ACK。

### 阶段与职责重读

阶段切换时核本人角色、目标、允许动作和下一负责人。已有授权继续有效；涉及新目标、资源或明确的 Human 验收点时找对应负责人。

新目标：Human 提出 → 成员调查并在本人 TODO 提交计划 → Coordinator 汇总 → Human 通过 → 整阶段自主执行。已授权维护和普通软修直接继续。

压缩前保存成果、Current 和未完事项；压缩后按上述四步实际重读。依据模型与 Harness 的容量提前压缩或换 Runtime。400K tokens 是容量足够时的本安装经验值；低容量模型更早处理，没有可靠读数不填写猜测值。

### 读取边界

核结果的范围、来源和时间；读不到就报告具体断点。查询范围内为空不能说明全局没有任务。联系状态表示入口是否可用；业务进展读本人 Current、原输入与实际成果。Current 陈旧时向原 Owner 核实，不能仅凭旧等待判定停工并重复派发。接口字段和性能判断见[接口参考](../Guides/guide-paos-interface-reference.md)。

## 自主推进

- 已授权且能做的工作继续做。只因具体外部等待、真实阻碍、责任完成或明确停止而待机；暂停受影响部分，其余继续。
- 处理澄清或副输入后回 Current 继续行动。清空 inbox、更新 TODO、发信和完成子项，都要接回总体目标。
- 专业问题直接找同事；运行问题找 Rooter；目标和优先级找 Coordinator。本人维护本人 TODO。
- 合作成果确定一位合成人，保存唯一交付稿，再交约定验收人；同事按需要直接交流。
- 阶段改变、成果形成或依赖解除时，同步 Current 与相关 Task。尚能继续实施时，下一次审阅写在下一步；真正交出候选后才写等待审阅。
- Notice 记录输入处理，TODO 记录本人行动，验收人记录接受。只处理本次实际办过的 Notice，并引用对应结果；`handled` 不表示整项任务完成。

普通软修直接维护唯一正文、引用和目录并提交，用随后真实业务看同类摩擦是否减少。无效时按 Git 撤回本次改动后换办法，保留后续成果。明确要求独审的代码或业务结果继续独审；没有业务样本时记待观察。

## 交付与收口

1. **保存成果。** 给出原件位置、版本、完成与未完成项、下一负责人及其动作。直接引用已有原件；候选、审阅、接受和安装分别写清。
2. **交给下一位。** 沿 Mail/Notice/Contact 正式交付，首次接续用 `agent send --remind`。分别核投递与提醒回执，再确认下游已读原件并开始工作。临时入口保持到实际消费或明确交回；关闭前交清接续位置。提醒失败按现有恢复条件处理；结果不确定先核原记录，不重投或换路制造重复业务。
3. **同步当前页。** 更新 Current、相关 Task、成果和接受原件引用。等待字段只留仍存在的依赖；完成项里残留旧等待时核事实后清理。需要的命令查[操作指南](../Guides/guide-paos-cat-operations.md)。
4. **顺手维护。** 按[文件准则的日常顺手维护](../Guides/guide-project-work-world.md#日常顺手维护)，把本次创建、采用、替换或交接的资料当场归位或登记稳定原件链接；更新本次影响的当前入口，已采用结果替下旧候选，历史原件保留。规则只改唯一正文，清掉本次触及的重复口径；相邻问题交原 Owner。
5. **归档并回报。** 已处理输入和已完成任务归档，在 Project 历史页留原件短索引。可采用成果、阶段完成、阻碍或重要取舍变化时，主动回报：完成内容与原件、剩余事项、下一负责人及动作、需要 Human 决定的事。
6. **回用经验。** 遇相似问题查已有 Tips；记录有价值的场景、做法、依据与适用条件。验证有效后，通用规则进唯一 Workflow/Guide，专业方法进 Skill，工具进 Tool Index，项目结论留 Project；原 Tips 标明去向。无新经验不凑条目。
7. **继续下一项。** 沿总体目标继续可执行工作；真正需等待时写清对象、原件和恢复条件。没有业务不造任务，旁支消息不自动打断主线。

在本人原 Harness 会话也给 Human 简短回报，附成果入口、总体剩余事项和下一步。

## 停止与等待

结束回合前看本次相关 pending 和本人未完任务。有可执行事项就继续；已有执行跟原句柄或原会话。无法恢复时把具体断点交负责人，写清等待。入口在线、页面更新时间、任务已投递，都不能单独证明业务完成。

当前回合直接工作，无须等自己被唤醒；沿现有接续机制，不加轮询服务或调度器。原会话被接替时停止执行并保留成果及外部进程状态。外部写入交接按 [Runtime 交接](../Guides/guide-runtime-handoff.md)；文件归位按 [Project 文件与 Git](../Guides/guide-project-work-world.md)。
