# 夜间整理

把白天的成果整理成明天能直接接续的入口。日常维护先由产出者或采用者在实际交付中按[Project 文件与 Git 的日常顺手维护](../Guides/guide-project-work-world.md#日常顺手维护)完成；本流程主要补漏、解除旧等待并把有效经验并回唯一正文。执行者处理遗漏的文件归位、明显失效的入口和普通软修；业务 Owner 维护任务状态与业务判断；Rooter 分配范围、处理运行问题并复核结果。

## 开始一批

沿[工作循环](wf-agent-work-cycle.md#恢复)恢复本人责任。先接上次未完批次，再看当天有变化的 Project、TODO、成果和 Library；只打开本次需要的原件。

选择少量具体对象，在本人 Current 写清要整理的文件、依据、完成标准和接续人。同一批次持续到完成或出现明确依赖，后一次定时唤醒继续原批次。

## 整理与优化

1. **对齐进展。** 对照实际成果、接受记录与当前页，找出旧等待、错误引用和漏掉的下一步。本人修本人 TODO；他人的偏差连同原件交原 Owner，确认其实际接住。已有验收直接引用。
2. **补漏归位。** 检查白天是否已按[Project 文件与 Git](../Guides/guide-project-work-world.md#日常顺手维护)完成本次资料维护；只补遗漏的归位、失效入口和必要引用，保留当前正文，归档已被取代的材料。有业务取舍的内容交 Coordinator 判断，不另造全盘扫描或日报。
3. **回用经验。** 反复出现的真实摩擦，先找已有方法；有明确改进就直接修唯一 Workflow、Guide 或 Skill，维护相关链接和目录。效果沿后续真实业务观察，无效时撤回本次改动并另找办法。
4. **准备接续。** 把剩余动作交给具体 Owner，给出原件与恢复条件。能够继续的已授权业务按[交付与收口](wf-agent-work-cycle.md#交付与收口)推进。

共享正文由当前明确的一位维护者修改。产品代码问题交 S010 组织；运行与安装问题交 Rooter。当天没有值得修改的内容，就保留实际结果。

## 清晨复核

执行者在既有成果位置保留一份当前结果：改了哪些文件、为什么、哪些事项仍待谁处理，并更新本人 Current。已完成项进项目历史短索引，细节沿原件或 Git 查阅。

Rooter 读实际差异与交接结果，接受有效整理，推动未完责任，纠正无效改动。普通软修按现有授权采用；业务状态由原 Owner 确认。下一夜优先处理留下的具体问题。

## 运行条件

具体工位、时间和结果路径放在本安装的任务交接中；自动任务只负责唤醒与定位本流程。维护变化记录在原 Project 或本人任务中，平稳无变化时保持安静。

模型按当前授权和产品实际状态选择。夜间免费活动须核当前标志、有效期与时间窗；延迟执行时按实际时间判断。提前保存 Current 和成果，再按模型容量压缩或换 Runtime；恢复顺序沿工作循环。

入口不可用时保存本批次与首次回执，由 Rooter 沿已有正常路径恢复。未知交付先查原记录；受理、本人读件、实际修改和接受分别按真实结果记录。
