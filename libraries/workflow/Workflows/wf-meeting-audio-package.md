# 会议与录音中间包

一场会有文字记录、可能还有全天录音时：先分证据等级，再写内部件，最后才写对外周结／日更。对外件不是会议纪要，是从记录里挑出「影响下一步动作」的事实。

## 一、证据分档

| 档 | 来源 | 用法 |
|---|---|---|
| A | 会议文字记录（带说话人与时间码） | 可引用，内部件标时间码 |
| B | 现场原件（日志、截图、实测数据） | 可作事实，注明条件 |
| C | 本地机器转写 | 只用于定位，不作结论 |
| D | 摘要、群消息、AI 纪要 | 标待核；数字必须回原文 |

- 会议内偏移不是钟表时间。
- 说话人姓名只在记录已标名时写，其余保留「说话人 N」。
- 口头估计不是实测。原话是「我感觉…」的，不能写成「实测」。

## 二、内部件与对外件分工

原始材料保留原件；内部件写关键脉络、来源定位和待核项。对外件写影响判断与行动的进展、卡点、下一步；必要规格和来源可以保留，其他推导、过程与内部讨论放内部件。条数由当前任务决定。

## 三、周结稿示例（2026-10-27 群发稿）

以下为 2026-10-27 周结稿示例（群发稿），作为格式与尺度基准；缺发送凭据，不写成已实发或 Human 采用原文。

> **周结（10-21 至 10-27）**
>
> **阶段目标（11-06 前）**：demo 样车把动力系统测完，出完整测试报告——实测电性能、功耗和仿真对得上；各环节出报告，运控汇总，通信延迟一起测完。
>
> **本周**
>
> - **控制**：原地站立已稳，抖动消除。限力矩约 2.8 N·m，后续逐步放开；站立功率 20–30W。
> - **感知**：定位到双目驱动把 WiFi 卡死，跟数据量无关，这是本周最实的结论。定位误差 0.7–0.8 米，本周收尾。
> - **Beni**：头部拆完，主控与内存配置摸清，产品功能性能进行了梳理，另一颗处理器型号待查；下部未拆。
>
> **下周**
>
> - **控制**：加减速、上坡、下坡逐项测，每项记工况与档位；补主控到各关节的通信延迟；功耗拆到单电机，和整机分开列；测完与仿真对齐。
> - **感知**：先解双目与 WiFi 的 SDIO 冲突，再重测埋点和定位数据；输出当前精度与优化方向。
> - **Beni**：拆下部与底盘板，量供电；查清协处理器型号与规格书。
> - **交付**：各环节报告本周内出齐，汇总成 demo 样车测试报告，下周周五前交。

从这份范例可提炼以下写法参考：

1. **阶段目标一行说完**：期限、对象、验收、交付，四件事都在这一句里，不分点、不解释。
2. **本周每条只留状态与数字**：站起来了、力矩多少、误差多少、拆到哪。没有过程，没有会议细节。
3. **每个域一句话到两句**，不加副词修饰，不写「取得了…进展」这类空话。
4. **卡点可省**：卡点已经隐含在下周动作里时，不必单列一段。
5. **下周按域给动作，最后一行给交付**：动作带对象（测什么、记什么、拆什么），不发散。
6. **本例不写时间码**：需要来源时保留必要来源，出处细节可留内部件。

## 四、日更的写法

按当前任务或 Human 指定格式组织；常用「阶段目标 → 背景 → 今日/进展 → 明日/下一步」，但不强制固定四段。条数随实际信息，不硬凑；规格参数可保留当时的必要语境。内容、作者归属与版本规则见[文档编辑·内容、作者与版本](../Guides/guide-document-editing.md#内容作者与版本)。

- **已采用样例**：2026-10-20 Human 实际采用版见 [日更同步模板](../../skill/project-progress-sync/assets/日更同步模板.md) 的「已采用的实际样例」，原消息来源见 [SOURCE-HUMAN-DAILY-20261020.md](C:/Users/remo/Desktop/agent学习计划/PAOS-Projects/3002-Personal-Agent-OS/Works/WORKFLOW-REUSE-FRICTION-20261028/SOURCE-HUMAN-DAILY-20261020.md)。只链接，不复制第二份正文。
- **2026-10-26**：现有件是源稿；Human 当日实发逐字版本未留档。
- **2026-10-27**：日更为群发稿，无采用记录；同日周结是周结稿示例，不当作日更采用版。
- 今日与周结的“本周”同口径，明日与“下周”对齐；某项没有进展就不写。

## 五、转写

- 本地优先，音频不外传；分块＋断点续跑。
- 模型量力选，同一批不中途换模型。
- 转写跑起来后不要等：先用文字记录出结果，转写完成再补。

## 六、写入计划

1. 写前留快照：文档 token、revision、插入锚点。
2. 沿该项目既定写入权限与 Owner 分工更新当天进度和次日计划；节点表等结构是否修改由该项目 Owner 决定。
3. 写完回读标题顺序与文字；期限类变化（如顺延）写在进度章，节点表交主管定。

## 七、常见错误

| 错误 | 处理 |
|---|---|
| 把口头估计写成实测（续航「30 分钟」是估计） | 回原文，标估计 |
| 把别的议题的时间码当本议题安排 | 回看上下文 |
| 把会上讨论写成当前状态（抖动已解决但会上仍在讨论） | 分「会上状态」与「收盘状态」 |
| 对外件堆无关细节或冗长过程 | 只留影响判断/行动的信息，其余留内部件 |
| 把无关时间码或内部缩写带进对外件 | 需要来源时保留来源，过程细节留内部件 |
| 只写文件路径不验证落盘 | 写完回读 |

## 八、收口

内部件与对外件分目录保存；原件与转写留中间包；计划回读结果与 revision 记进 Current。当天没有新材料就不制造日更。
