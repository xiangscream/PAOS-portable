# 简明表达规则

适用于指南、派工、TODO、交接和状态汇报。

1. **一句一意。** 动作句用明确动词，主动语态；每步写清对象和结果。
2. **术语统一。** 同一概念用同一词；文件名、参数、状态名保持原拼写，首次出现给一次解释。
3. **结果或动作在前，原因在后。** 条件放在动作前；长句拆开。
4. **流程给四样：** 输入、步骤、成果位置、完成条件；交接说明接续者与下一步。
5. **删去防御性套话和审计腔**（“为保证严谨”“不能冒称”“证据闭环”）；**保留影响行动的条件、错误和限制**，用短句写。
6. **发布正文写当前规则。** 历史与过程放 Git，追溯给一条链接。
7. **可选辅助**：clean-writing skill（共享 Skill Library 索引）可作为写作辅助，不是第二份强制正文。

## 中文与英文的分工

- 中文（日常写作）：借鉴 ASD-STE100 的表达原则；**“删防御性套话和审计腔”是 PAOS 要求，不属官方 STE**。不用英文字数。
- 受控技术文档（英文与中文）：走 [ASD-STE100 受控写作](guide-asd-ste100.md)。中文轨沿用同一套规则，只放宽词库；官方资料与下载入口见该页。

## 真实改写样例

| 原写法（真实笔） | 改写 |
| --- | --- |
| S040 核对页：“四层判据全部达成”（但验收栏待 S010） | 发送和原线程消费完成；待 S010 验收。 |
| S031 整份 TODO 回告 | 已完成指南更新。产物：<原件路径>。下一步：S029复核。 |
| 指南连续段 “不可冒称/不代/不造…” | 读取本人 ENTRY 和 TODO，继续当前任务。 |
| “投递受理不构成消费证据，不能冒称业务闭环” | 邮件已送达；接收者尚未处理。下一步：S010 读取并接续。 |

## 必要限制（防误读）

- 不删真实错误、风险、限制、条件；给它们留短句。
- 不用本页把事实/证据说成空话；影响行动的信息与合规需要的核验不受本页压制。
