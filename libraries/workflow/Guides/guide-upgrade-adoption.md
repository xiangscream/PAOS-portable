# 发布采用与回退

受影响范围由本次授权和真实读写合同确定。记录 Source、Library、配置与运行版本，读 `health` 和 `install show` 核实际安装。文档小修直接修改、同步引用/Catalog并正常提交；不要给无关服务制造重启。

## 候选与正式入口

新增或修改CLI/API前，先用 `paos install show` 确认正在使用的 `source_root`。候选代码在独立工作树开发、审阅和修订；正式 Source 保持已采用版本，正常发布后由安装人更新。代码和配套指南一起交付。正式 Library 保留与实际安装能力相符的正文，接受后与代码一起采用。

已有能力的普通软流程修订继续按原权限直接维护发布。指南引用正文只维护一处，当前入口在采用时更新，旧原件留历史。

验证目录由各执行方分别持有，是否保留或清理依据既有阶段结果。保留别人仍在使用的目录，由原持有人在交接完成后归位或清理。

## 按变更范围复用验证

比较已接受版本与待发布版本的实现、依赖、运行入口和环境，确定本次影响范围。未变范围沿用原版本的已接受验证，本次补齐受影响检查；回报列出证据版本、覆盖范围和实际执行项。逐项核 Source、Core、CLI、页面和 Library 的实际采用，按受影响组件安排重载。

CLI/API 检查先走用户使用的公开入口，在隔离目录复用安装中的 Project/Rooter 布局并读回对应结果。正常路径通过后，再补本次改动涉及的边界。

- 从准确 Git 提交的差异确定发布文件集合，包含隐藏目录和派生索引。冻结目录用于保存原件，不能代替完整变更集合。
- 更新现存 UTF-8 生成管理文件时，用已接受的 before/after 生成器按通用换行文本合同比较。匹配 before 才更新，原字节先备份；已是 after 的复用，手改与暂停例外保留。内容未变的文件不重写。

## 统一采用的完成标准

1. 已批准改动进入正式版本，受影响的服务、命令或配置实际采用该行为。
2. Windows/WSL入口与安装描述一致；旧路径退出当前使用，原会话、模型和历史证据保留。
3. 成员从固定入口继续真实责任；暂停、人工或离线成员保留明确例外，不制造签收任务。
4. 需要接续的实际工作已被下游读取并开始处理。没有新业务样本时，运行效果记待观察，不派测试标记。
5. 旧文件实际归档，当前引用和 Catalog更新。未解决例外留负责人、范围及解除条件。

## 数据转换与回退

改数据或替换写入者前，保存可恢复原件，核源集合与活跃进程。在同一发布记录固定切换范围；已核互不兼容的组件共同切换，不另造临时兼容层。

失败时暂停受影响的新写入，保存新增业务后恢复对应数据、代码和入口。已经发生的业务证据不改写。升级、回退和结果沿同一记录，不新增审批账本。

## 公告与接续

给受影响成员一份正式说明：当前版本、变化、操作入口、下一步与回流位置。成员只在事实变化时自改 Current并回真实结果；Rooter修安装，Coordinator处理项目责任。

实际接续按 [工作循环](../Workflows/wf-agent-work-cycle.md#交付与收口)。旧发布快照在 [Archive](../Archive/README.md)。
