## 原始结果一：实施可执行性审查

### 约束复述

1. G0 的唯一目标是建立独立、私有、可重建、可恢复的本地仓库基线；不是开发新功能。
2. 两个原型必须以复制、最小改动、行为不变方式迁入 `personal-agent-os`，保留原目录名。
3. 允许来源仅为 Dashboard 原型、Memory Pipeline 原型，以及指定的 4 篇学习文档。
4. Dashboard 仅纳入迁移图列出的 12 项；Pipeline 仅纳入列出的代码、schema、synthetic-vault、测试与文档。
5. 不纳入 `build/`、缓存、日志、PID、浏览器 localStorage、数据库、真实 Inbox、真实 Vault、Key、公司内网配置、agent-co 源码/raw logs、模型和 NAS 配置。
6. 目标根目录需补齐启动、验证、安全、恢复、版本历史、ADR 和学习文档；解释决策原因而非只列命令。
7. 验证须从 `synthetic-vault` 重建派生数据，并通过 17 个管道、10 个 Dashboard、5 个本地服务测试（共 32 个）。
8. 还须验证 HTTP 200、`/api/health` 的 `ok: true`、LRC101 三项执行契约字段、来源 URL 安全性、Inbox 未被跟踪，以及删除 `build/` 后可重建。
9. Phase A 只做 Dry Run：输出计划目录树、逐项源/目标映射、文件数、排除项、风险文件、预期代码修改数、预计跟踪文件、回退方式。
10. Phase A 严禁创建目标目录、复制、初始化 Git、修改来源、建远端仓库、commit/push/PR；输出后必须等待 Phase B 的明确批准。
11. 任一需改来源、删除/移动文件、重命名原型目录、接入真实数据/Key/数据库/网络服务、加 remote/push，或三轮同问题失败，均停止。
12. 回退只恢复出错的对应文件，再重建与复测；不得整体覆盖工作区或专属空间。

### 判断

可以直接执行 Phase A。它是纯只读检查，文档层面没有 blocker。

### 发现的问题

Important：

- “两原型原样迁入”与“白名单式纳入”并存；应明确原样指选中文件内容与目录名不改。
- `synthetic-vault/` 没有逐文件清单，必须在 Dry Run 展开并扫描。
- `docs/architecture/`、`docs/runbooks/` 没有指定文件，空目录无法被 Git 跟踪。
- Dry Run 未冻结源快照；应记录逐文件大小、哈希和时间。
- 启动脚本缺少固定参数、工作目录、端口和生命周期规范。
- 前端设计书记录的是既完成变更，G0 不应据此重新实现或修改 v1.2。

Minor：

- 远程仓库已存在但 Phase A/B 不操作它，这只是背景而非依赖。
- “新目录从零生成”仅适用于获批后的 Phase B。
- 四篇学习文件的精确存在性应在 Dry Run 核对。

### 建议只读检查顺序

1. 检查目标路径是否不存在或为空。
2. 检查三处允许来源存在、可读并记录时间。
3. 对照白名单枚举 Dashboard。
4. 对照白名单枚举 Pipeline，并展开 `synthetic-vault/`。
5. 核对四篇指定学习文档。
6. 生成路径、目标、大小、修改时间和哈希清单。
7. 扫描敏感项，只报告路径和风险类型。
8. 检查路径依赖、路由、测试入口和运行环境。
9. 核算文件数、代码修改数（应为 0）和 Git 候选/忽略清单。
10. 输出目录树、风险、恢复方式和停止条件，然后等待批准。

## 原始结果二：安全与架构审查

### 判断

有条件通过；Phase A 可以交给实施 Agent。

### Important

- “预计修改的现有代码文件数量”可能被理解为允许兼容性修改或重构。
- `git init` 与“首次提交前候选变更”没有明确排除 `git add` 和本地 commit。
- “新机器部署”和“恢复上一个版本”缺少运行时版本、端口前置条件和首个可恢复版本。
- `synthetic-vault/` 整目录纳入前缺少明确敏感扫描前置条件。

### Minor

- 32 项测试之外的 HTTP、字段与安全验证缺少可重复命令和失败标准。
- “原样迁入”缺少 Phase B 的逐文件哈希回核。

### 最小修订建议

1. 预计修改现有代码数必须为 0；不兼容时停止。
2. 只允许 `git init` 和只读检查；禁止 `git add`、commit、remote、push、PR。
3. Dry Run 加入相对路径、大小和 SHA-256，Phase B 回核。
4. `synthetic-vault/` 敏感扫描通过后才可复制。
5. 记录 Python/Node/PowerShell 版本、启动前置条件、验收命令和预期输出。

### 最终结论

可以交办 Phase A，输出 Dry Run 后必须停止；不得因任何发现自行进入 Phase B。
