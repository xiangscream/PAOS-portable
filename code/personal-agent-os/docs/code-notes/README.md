## 三条贯穿全篇的原则

**读代码时遇到的注释往往就是设计说明。** 这个仓库的注释写得比文档准，比如 `local_server.py:120-124` 解释路由为什么用 `fullmatch`，`project_store.py:719-733` 把锁内顺序写死，`paos_wakeup.py` 开头解释崩溃时为什么留 uncertain 而不是重试。读文档之前先看代码注释。

**分清"存在实现"和"已证成"。** 代码里有某个函数，不等于它被调用；文档说某个能力可用，不等于它通过了验收。批注里凡是没有证据的地方都标了"未核实"。

**判断完成要看多个事实。** 唤醒被接受不等于任务跑完，Pack 落盘不等于 Agent 读了。系统里的每一条记录只证明它自己那一步。
