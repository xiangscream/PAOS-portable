## 1. 角色

### 用户｜Product Owner

决定主线、真实资料范围、是否合并，以及系统是否真正改善工作。

### 设计 Agent｜Architect / Maintainer

维护一个当前计划和一个可执行任务；发现元工作超过实现价值时主动删减流程。默认不替实施 Agent 重复实现。

### 实施 Agent｜Executor

在隔离分支完成任务、测试和 Draft PR。只有触发停止条件时才把选择交回用户。

### 审查 Agent｜按需角色

不再默认加入每个任务。只在以下情况使用：

- 数据所有权或隐私边界变化；
- 破坏性文件操作；
- 权限、Secret 或外部部署；
- 冻结规格需要歧义探针；
- 实施连续失败，需要独立最小复现。

## 3. T-002 的简化执行

T-002 是 L1：隔离分支内、Git 可回退的代码迁移。

```text
快速预检
  → 复制 32 个白名单文件
  → 只修复 Inbox 路径与对应测试
  → 32 项测试 + HTTP 验证
  → 敏感扫描
  → commit / push / Draft PR
```

不再在预检、实施和 PR 之间设置三次人工批准。预检只确认来源数量、排除项和工作区隔离；结果正常就继续。

必须停止的情况：

- 扫描到真实资料、Secret 或公司内部信息；
- 需要修改允许范围外的产品逻辑；
- 来源目录或文件数量与任务包不一致；
- 需要移动、删除或覆盖来源；
- 需要自动安装软件、改权限、杀进程或开放网络；
- 同一问题三轮仍无法最小化。

## 4. 风险对应流程

- L0 只读：直接做；
- L1 可回退代码/文档：实现、测试、PR；
- L2 用户资料或不可重建文件：Dry Run、批准、校验；
- L3 删除/覆盖/Secret/权限/部署：快照、恢复验证、精确批准。

文件数量只是风险信号，不是机械 Gate。有 Git 保护的 32 个代码文件属于 L1；真实 Vault 中 21 个既有笔记属于 L2。
